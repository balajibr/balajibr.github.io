Why this was filed Scanners were never the bottleneck. An enterprise could already scan its applications, operating systems, container images, and network and drown in findings from four different tools that did not talk to each other. Nobody automated the judgment after the scan: reconciling those four report streams into one non-duplicated view, and then deciding what would actually happen if you applied the fix, because in production the remediation itself carries risk. Onix built a system that scores what the remediation itself would do, then lets that score gate whether the fix runs automatically. That gate is what this patent claims.

I.Three Modules and a Threshold

Claim 1 is compact for a system claim: three modules, not six. The report generation module 110 produces four named scan reports across the software delivery pipeline. The recommendation engine 112 carries five distinct configured behaviors, and is where nearly all the claimed intelligence sits: analyze, verify against the CVE database 120, run an impact analysis with a machine learning model, generate a score matrix against a predefined threshold, and issue recommendations. The vulnerability remediation module 114 then does one thing, which is to use those threshold limits to initiate automated remediation. The claim’s weight rests on what the threshold is computed from.

II.Method 400: Eight Steps

Claims 11 and 12 restate the system as method 400, steps 402–416. Five of the eight belong to the recommendation engine. The order matters and is claimed: verification against the CVE database (408) comes before the impact analysis (410), so that false positives and duplicates are removed before the machine learning model spends its judgment on them, and the score matrix (412) is generated from that analysis rather than from raw scanner severity.

IV.How This Differs From Existing Tools

Vulnerability management is a mature market, and risk-based prioritization is its standard feature. Tenable’s VPR, Qualys TruRisk, Rapid7 Active Risk, and Wiz’s attack-path analysis all rank findings by exploitability, asset criticality, and threat intelligence rather than raw CVSS. Every one of those scores how dangerous it is to have the vulnerability. The claimed system asks a different question. Its machine learning model conducts an impact analysis to “determine the consequence of fixing” the vulnerability, meaning the side effects the fix itself would introduce, and the resulting matrix is what gates automatic action.

Reading this fairly The comparison reflects the landscape around the November 2024 filing, and this market moves quickly, and several vendors have since expanded their automated-remediation and blast-radius-prediction features, so a current head-to-head would need re-checking. Predicting remediation side effects is also not a new idea on its own. What the patent claims is the specific chain: four scan streams reconciled, CVE-verified, ML-analyzed for the consequence of fixing, scored into a matrix, and that matrix’s threshold used to release the automated remediation, all as one system.
